
## Native CarCast Receiver milestone — first implementation slice

The isolated `feature/native-receiver` branch adds a native Android/Android TV receiver path while leaving the tagged Browser Receiver baseline unchanged. Repository audit found an older custom TLS + MediaCodec receiver; the new user path instead uses `NativeReceiverWebRtcService` and `NativeWebRtcSenderService`. Existing TLS 1.3/SAS identity, `_carcast._tcp.` discovery, and the sender's proven `BrowserWebRtcSession` capture/audio pipeline are reused. SDP and ICE signaling are framed inside TLS; video and optional device playback audio use WebRTC DTLS-SRTP and native Android rendering/output.

The receiver advertises only while intentionally enabled, filters discovery to `native-webrtc-v1`, hides raw endpoint data from normal UI, shows an explicit receiver approval request with SAS, enforces one active sender, supports optional Android TV launcher metadata, and tears down sockets, NSD registration, PeerConnection, renderer, and executor on stop. The native sender requests MediaProjection only after receiver approval and uses the existing ScreenCapturerAndroid ownership path.

Validation completed in Sandbox: `./gradlew clean testDebugUnitTest assembleDebug` passed, the debug APK was generated, and Browser Receiver source files had no diff on this branch. Physical phone-to-phone, Android TV, device-audio, portrait/landscape, D-pad, brief network interruption, and hardware WebRTC interoperability tests remain required. Native stats mapping, rename settings UI, and persistent trusted-device management remain follow-up work; this slice is not claimed as physically verified.
